# Шпаргалка защиты DW-1

## Одна фраза о проекте

DW-1 находит в письмах следы генеративного ИИ **по элементам** и оценивает **намерение**
письма отдельно от происхождения, группирует письма в кампании и объясняет решение
аналитику SOC (Doctor Web).

## Главная идея

- **Две независимые оси**: `ai_provenance` (кто написал: человек/ИИ/шаблон) и `intent`
  (зачем: фишинг/спам/легитимно). «Написано ИИ» ≠ «злонамеренно».
- **Позлементность**: тема, тело, CTA, HTML, ссылки, заголовки, изображения, QR, шаблон.
- **Объяснимость с измерением**: faithfulness (comprehensiveness/sufficiency).
- **Кампании**: MinHash/LSH + Jaccard + HDBSCAN; топ-50 оценивается по BCubed.
- **Калибровка**: вероятности калибруются (isotonic), есть порог отказа (unknown).

## Вопросы и ответы

- **Чем отличаетесь от GPTZero?** Две оси, позлементность, кампании, калиброванные
  вероятности, контр-свидетельства, измеренная устойчивость к атакам, объяснения с faithfulness.
- **Почему RU не работает?** Qwen 0.5B и GPT-Neo слабы на RU (AUC ~0.36–0.38); разрыв измерен,
  нужен крупный RU-capable детектор — следующая итерация.
- **Почему BCubed — прокси?** Ручная разметка 2–3 человек не успела; прокси по cosine
  (0.90/0.75, 131 расхождение) даёт ориентир: 0.900/0.689. Workflow ручной разметки готов.
- **Почему перенос AUC 0.5?** TF-IDF ловит конкретный генератор/домен; на невиданном
  домене — случайное угадывание. Это честный аргумент за вероятностные детекторы/ансамбль.
- **Почему детекторы почти идеальны на письмах?** Классы разделены по источнику
  (LLMGen vs Nazario), тест 23 письма — оптимистичная оценка, не «дикая» почта.
- **Данные и этика?** Внутренние письма не покидают контур; в облако — только публичные
  данные с подтверждёнными лицензиями; сырые письма не публикуются в открытом GitHub.
- **Dual-use?** Генерация — только на синтетических получателях; система — защитная,
  для SOC-аналитика, с прозрачными объяснениями.

## Как показывать (3 минуты)

1. Сайт Sprint 3 (`reports/sprint3-site.html`) → схема пайплайна и роли;
2. Карточка письма: две шкалы + калиброванная уверенность + кампания;
3. Таблицы: калибровка/FP/operating points (Sprint 2), Qwen/письма/атаки/BCubed (Sprint 3);
4. Матрица переноса (Sprint 4) — честный разговор об ограничениях;
5. Итог: что работает (EN, intent, устойчивость, легит-почта), что ограничено (RU, перенос).

## Ограничения (проговаривать самому)

1. RU-детекция ИИ — ограничена; 2. Перенос TF-IDF ≈ 0; 3. BCubed — прокси-gold;
4. Fast-DetectGPT проверен на публичном бенчмарке, не на почте заказчика.
