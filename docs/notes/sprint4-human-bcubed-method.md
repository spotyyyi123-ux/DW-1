# Sprint 4, задача 3 — человеческая разметка кампаний

Статус 2026-11-13: **пакет для людей подготовлен; независимые ответы ещё не получены**.
Человеческий BCubed F1 пока не измерен. Прокси-результаты Sprint 3 не заменяются
человеческими цифрами до завершения разметки и согласования.

## Подготовленная выборка

Используется переданный владельцем данных приватный review.zip:
50 непересекающихся кластеров, 600 уникальных писем. Проверены хеш пакета, хеши
текстов, замороженное разбиение, полнота ID и разрешение внешней обработки.

- SHA256 архива: `4009c8928bbf3e7bed21f67b1776862910d1898dccb3b9adcf48d1af17bab471`.
- ID пакета: `be029c061a53aaeff24615d5cc3b83055a6166375983bdc5762d3d8a1c0a2377`.

Исходная кластеризация содержала пересечения. По описанию владельца данных
(`scripts/build_campaign_review_inputs.py`) они устранены жадно: исходные кластеры
сортируются по убыванию размера; при равенстве используется строковый cluster_id,
а при отсутствии/равенстве ID — стабильный порядок исходного файла. Документ остаётся
в первом принятом кластере; группы с менее чем двумя новыми участниками пропускаются.
Затем выбирается топ-50 по получившемуся размеру и ID. Это процедура подготовки
выборки, а не человеческая разметка и не результат HDBSCAN.

Исходный clusters.json до устранения пересечений в полученный архив не входит:
само преобразование независимо не воспроизводилось. На полученном замороженном
разбиении подтверждены отсутствие пересечений и совпадение всех хешей.

## Что входит в приватный пакет

- START.html: выбрать страницу A/B/C.
- reviewer-A.html, reviewer-B.html, reviewer-C.html: один и тот же набор без готовых
  групп и оценок. Никакие ответы из annotation.jsonl или прокси-файлов не подставляются.
- INSTRUCTIONS.txt: короткая инструкция.
- protocol.json и status.json: состав, хеши, правила и статус; метрика пока null.
- human-review.zip: всё перечисленное для передачи участникам вне публичного Git.

Каждый из 2–3 разных людей независимо проверяет **все 600 писем**.
Не делить письма на три части и не сверять ответы до сдачи файлов.
Можно работать частями: «Сохранить черновик» → позже импортировать JSONL в ту же
страницу A/B/C. Смена страницы не переносит чужие ответы.

Один шаблон — одна глобальная истинная группа, даже если письма находятся в разных
предсказанных кластерах. Переменные имена, суммы, бренды, URL не всегда означают
разные шаблоны. Одинаковая тема/подпись или близкая тематика недостаточны для near-dup.
Одиночка получает свою группу. Незавершённые и сомнительные записи не допускаются
к экспорту готового результата.

Готовый JSONL содержит структурированные ID/хеши/метки и декларацию участника,
**без текстов писем и свободных заметок**. Это самостоятельное подтверждение человека,
а не техническое доказательство личности или реальной независимости.

## Подготовить заново

```powershell
python -m dw1.campaigns.human_review --package C:/path/review.zip --out data/runs/sprint4/human-review --reviewers 3
# Или через Makefile:
make human-review REVIEW_PACKAGE=C:/path/review.zip HUMAN_REVIEWERS=3
```

Непустой каталог вывода не перезаписывается, чтобы не потерять работу участников.
Локальный torch не устанавливается; для подготовки пакета и ручной разметки он не нужен.

## После получения файлов

1. Собрать human-A-*.jsonl и human-B-*.jsonl (третья независимая разметка опциональна).
2. Сравнить состав групп, независимо от их названий. Обсудить расхождения.
3. Если люди согласны и разбиения совпадают, итоговым может быть один из их файлов.
4. Если группы меняются при согласовании, подготовить итоговый файл с
   stage=adjudicated, annotation_source=human, protocol=dw1-human-independent-v1,
   human_confirmed=true и именем человека, выполнившего согласование.
5. Записать adjudication-record.json с ID пакета, SHA256 всех файлов проверяющих,
   SHA256 итогового файла, именем согласовавшего и решениями по спорным/изменённым ID.

Пример структуры записи согласования (хеши и ID подставляются по фактическим файлам):

```json
{
  "protocol": "dw1-human-independent-v1",
  "package_id": "ID_ПАКЕТА",
  "reviewer_annotations_sha256": ["SHA256_A", "SHA256_B"],
  "final_annotations_sha256": "SHA256_ИТОГОВОГО_JSONL",
  "adjudicated_by": "имя или ID человека",
  "human_confirmed": true,
  "decisions": [{"ids": ["спорный-ID"], "reason": "почему принят этот состав группы"}]
}
```

Все ID с разногласиями или изменившимся составом итоговой группы должны иметь
описанное решение. Изменение файла разметки после согласования меняет хеш и требует
нового подтверждения. Просто непустого имени в --adjudicated-by недостаточно.

```powershell
make eval PY=python HUMAN_GOLD=1 REVIEW_PACKAGE=private/review EMBEDDINGS=private/embeddings.npz ANNOTATIONS=human-final.jsonl REVIEWERS="human-a.jsonl human-b.jsonl" ADJUDICATION_RECORD=adjudication-record.json
```

При полном согласии без изменения групп ADJUDICATION_RECORD не нужен.
Новый человеческий результат по умолчанию сохраняется отдельно:
`data/runs/sprint4/campaigns/human-eval/`, отчёт — `docs/notes/sprint4-human-bcubed.md`.
Старый отчёт Sprint 3 сохраняется как прокси-оценка.

Формула и популяция прежние: BCubed по всем 600 участникам исходных топ-50,
сравнение baseline и LSH+HDBSCAN на одной выборке, включая шумовые одиночки.
Это не оценка всего исходного корпуса.

## Публикация

HTML и ZIP содержат реальные письма и не добавляются в публичный Git.
`inputs/` и campaigns_v2.json также остаются приватными: в них есть исходные тексты.
Для публикации предназначены проверенные файлы `public/`, метрики, ID/хеши,
предсказания без текстов и разрешённые эмбеддинги. Причины согласования могут цитировать
письма: публичная копия хранит только их хеши, полные причины остаются в приватных входах.
