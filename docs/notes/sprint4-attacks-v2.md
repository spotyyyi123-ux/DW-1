Исходный бенчмарк, веса моделей и внешние скоры сейчас не предоставлены.
По согласованию с пользователем подготовлен код и пакет запуска. Старые метрики
Sprint 2 и результат ансамбля на 23 письмах не используются как результат этой задачи.

## Что готово

- Семь прежних атак по правилам и восьмая `llm_paraphrase` с настоящей внешней LLM.
  Старый `paraphrase` не является LLM-вызовом; имитация обратного перевода также остаётся правилом.
- Замороженная сетка: clean и восемь атак × четыре интенсивности. Все 600 ID
  присутствуют в каждом условии. Меняется тело исходных AI-писем; человеческие
  письма остаются контролем, как в старом эксперименте. Тема, HTML, картинки,
  заголовки и вложения в этот отдельный эксперимент моделей текста не входят.
- Внешний GPU-ноутбук без локального torch: генерация перефразов и повторный
  Fast-DetectGPT на **каждом изменённом тексте**, фиксированные ревизии моделей,
  сохранение промежуточных результатов. Загрузка Google Drive не требуется.
- Защита URL, адресов и чисел от изменения. После генерации создаётся приватная
  `semantic_review.html`: человек подтверждает сохранение смысла, фактов, имён,
  действия, срочности и языка. Непроверенные перефразы к финальному расчёту не допускаются.
- Локальная калибровка TF-IDF, Fast-DetectGPT и intent только на чистой validation.
  Ансамбль — среднее двух вероятностей **provenance**; intent считается отдельно.
- Сохранение `predictions.parquet`; `make eval ATTACKS_V2=1` строит из него
  JSON, CSV, SVG-кривые и текстовый отчёт с выводом по intent и ограничениями.

## Что передать для настоящего запуска

1. `data/sprint2/bench/`: 600 реальных `.eml` и `labels.csv` с колонками
   `file,provenance,intent,source`. Метки: `human|ai_generated` и
   `legitimate|spam|phishing`. Файл — basename внутри папки. Все письма должны
   иметь непустое текстовое тело; пропуски, дубли и HTML-only требуют решения
   до заморозки, а не молчаливого удаления из выборки.
2. Доверенные веса команды `prov_model.joblib`, `intent_model.joblib` и `models.json`
   по [образцу](../examples/attacks-v2-models.example.json). Нужны SHA-256,
   версии и **полные** списки SHA-256 обучающих текстов и нормализованных тел для обеих моделей.
   Порядок классов `0,1`. Списки не должны пересекаться с экспериментом;
   модель, обученная на этих 600 письмах, для отложенной оценки не подходит.
   `training_text_sha256` — SHA-256 точных UTF-8 байтов обучающего текста.
   `training_body_normalized_sha256` — SHA-256 тела после
   `" ".join(body.lower().split())`, включая извлечение тела из обучающих писем
   с префиксами Subject/From. Нужны происхождение обучающей выборки,
   `attested_by/attested_at` и политика `exact-utf8+body-lower-whitespace-v1`.
   Полнота списков — утверждение владельца артефактов, не доказательство личности;
   неизвестные списки нужно восстановить из обучения, а не поставить пустые.
3. `provenance.json` по [образцу](../examples/attacks-v2-provenance.example.json):
   публичность, подтверждённая лицензия, доказательство и разрешение на внешний
   **прогон атак** для каждого источника. Шаблон по умолчанию ничего не разрешает.
   Разрешение Сергея для BCubed не распространяется на этот эксперимент.

В старой выборке seven-phishing/enron имеют нерешённые лицензии/ограничения
экспорта. Её нельзя автоматически отправить в Colab по разрешению для кластеров.
Нужно разрешить именно этот способ обработки либо согласовать замену источников;
при замене фиксируется новая популяция, сравнение со Sprint 2 перестаёт быть парным.
Пакет `review.zip` содержит другие 600 писем для кластеризации и не заменяет
размеченный детекторный бенчмарк.

## Порядок запуска

Команды выполняются из корня checkout ветки задачи 2. Локально установите обычные
зависимости проекта, без extras `embeddings` и без torch/transformers.

```powershell
# Windows / PowerShell; python из окружения проекта
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python scripts/attacks_v2.py plan

# После получения данных и корректного provenance
python scripts/attacks_v2.py prepare --benchmark data/sprint2/bench `
  --provenance data/runs/sprint4/attacks/provenance.json `
  --out data/runs/sprint4/attacks/package
```

Результат: приватные `package/` и `package.zip` с плоской структурой.
Внутри — замороженные тексты/ID/сплиты, запросы LLM, manifest, provenance,
снимок внешнего runner, лицензия Fast-DetectGPT и ноутбук.
Для Colab можно переименовать `package.zip` в `external_bundle.zip`.
Откройте `scripts/external/attacks_v2_colab.ipynb` в Colab, выберите T4 и
выполните ячейки. Загрузите только этот приватный ZIP; веса joblib остаются локально.
Ноутбук фиксирует SHA ревизий моделей при старте. Для воспроизведения подставьте
сохранённые SHA из `run_config.json`, а не новую ревизию main.

Скачайте `external_results.zip`, распакуйте в `external/`, откройте
`semantic_review.html`, проверьте перефразы и скачайте заполненный
`semantic_review.jsonl`. При отказе проверки нужно исправить/перегенерировать
вариант с сохранением методики и повторно посчитать его FD-скор, а не удалить строку.
Каждая строка согласования привязана к package ID, исходному и итоговому хэшам.

```powershell
python scripts/attacks_v2.py score `
  --package data/runs/sprint4/attacks/package `
  --external data/runs/sprint4/attacks/external `
  --models data/runs/sprint4/attacks/models.json `
  --semantic-review data/runs/sprint4/attacks/external/semantic_review.jsonl `
  --out data/runs/sprint4/attacks/scored

# Эквивалент make eval ATTACKS_V2=1
python -m dw1.eval.attacks_v2 `
  --predictions data/runs/sprint4/attacks/scored/predictions.parquet `
  --out data/runs/sprint4/attacks/eval
```

Make-обёртки: `attacks-v2-plan`, `attacks-v2-prepare`, `attacks-v2-score`.
Пути настраиваются через `ATTACK_BENCHMARK`, `ATTACK_PACKAGE`, `ATTACK_MODELS`,
`ATTACK_PROVENANCE`, `ATTACK_EXTERNAL`, `ATTACK_SEMANTIC_REVIEW`,
`ATTACK_SCORED_OUT`, `ATTACK_PREDICTIONS`, `ATTACK_EVAL_OUT`.
В Windows без make используйте PowerShell-команды выше.

## Методика и пределы вывода

Если `labels.csv` содержит колонку `split`, нужны непересекающиеся
`validation`/`test` для всех строк. Иначе используется стабильное разбиение
80/20 внутри комбинаций меток по нормализованному хэшу тела. Файлы и порядок строк не влияют на него.
Для переданных сплитов сохраняется отдельная политика owner-supplied и фактические размеры.
В типичной сбалансированной выборке это 120 validation и 480 test:
**600 — вся популяция, не 600 тестовых наблюдений**. Для 600 тестовых писем
потребуется отдельная независимая калибровочная выборка и расширение протокола.

Калибраторы обучаются на clean validation, затем замораживаются.
Порог каждого сигнала выбирается там же при эмпирическом FPR ≤ 1%, с учётом ties.
Этот один порог применяется ко всем атакованным test-условиям. Фактический FPR
на test выводится отдельно; удержание ≤ 1% на новой выборке не гарантируется.
Старый способ заново выбирать порог на атакованной выборке здесь не применяется.

В отчёте есть TPR/FPR/F1/AUC/ECE, изменения относительно clean, число реально
изменённых текстов и intent TPR на AI-подмножестве. Последний нужен, поскольку
неизменный человеческий спам может скрывать падение общего intent TPR.
Вывод относится к замороженной модели **тела** письма и атаке AI-части;
он не доказывает устойчивость всего многокомпонентного фьюжна или всего спама.
Интенсивность LLM — инструкция о глубине перефраза, не гарантированная доля изменений.
Человеческое подтверждение смысла не заменяется проверкой URL и хэшей.

Скоры FD связаны с полным изменённым текстом, одной версией модели и снимком кода.
Короткие/слишком длинные тексты не исчезают из отчёта: неполный внешний прогон
блокирует финальную оценку. Локальный импорт также не принимает усечённые скоры.
Внешний runner сохраняет чекпойнты; для продолжения нужны прежние пакет и настройки.
Если длина не укладывается в заданный лимит, сначала согласуйте новый лимит/протокол.

## Артефакты

- Сейчас: `data/runs/sprint4/attacks/status/preparation.json` — агрегированный
  статус подготовки с `measured_messages=0`, без исследовательских метрик.
- После внешнего прогона: приватные перефразы, FD-скоры, manifest и ручная проверка.
- После локального score: `predictions.parquet` (без тел писем),
  `calibration.json`, `scoring_manifest.json` с хэшами входов.
- После eval: `metrics.json`, `degradation_curves.json`, `summary.csv`,
  `curves.svg`, `report.md`. Вывод об устойчивости появляется только тогда.

Сырые письма, приватные ZIP/HTML и перефразы в публичный Git не коммитятся.
Даже редактированные артефакты публикуются только в пределах лицензии источника.
Тестовые синтетические примеры проверяют код и не являются результатом на 600.
