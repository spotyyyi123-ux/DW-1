## Часть 1. Подготовка машины (день 1)

### Шаг 1. Проверь Python
Открой командную строку (Win+R → `cmd` → Enter):
```cmd
python --version
```
Должно быть `Python 3.12.x`. Если нет — поставь с python.org (**галка «Add Python to PATH» обязательна**).

### Шаг 2. Скачай проект
```cmd
git clone https://github.com/spotyyyi123-ux/DW-1
cd DW-1
```
Все следующие команды — внутри этой папки (проверка: `cd` показывает путь, заканчивающийся на `DW-1`).

### Шаг 3. Создай окружение
```cmd
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
```
Вторая строка качает пакеты, займёт несколько минут.

### Шаг 4. Проверь, что всё работает
```cmd
.venv\Scripts\python -m pytest
.venv\Scripts\python scripts\smoke.py
```
Должно быть: `17 passed` и `SMOKE OK`. Если красное — **не чини сам**: скопируй ошибку и пришли наставнику.

### Шаг 5. Посмотри, что система умеет уже сейчас

`fusion` (две оси: `ai_provenance` и `intent`). Напиши в чат команды 2–3 предложения своими словами, что увидел.

## Часть 2. Первая задача: представься команде (первый PR)

Цель — не сам реестр, а **отработать процесс**: ветка → коммит → пуш → PR → мёрж.

1. Обновись до последней версии:
   ```cmd
   git checkout main
   git pull
   ```
2. Создай ветку. A → `w1/roster`, B → `w2/roster`, C → `w3/roster`:
   ```cmd
   git checkout -b w2/roster
   ```
3. Открой `docs/notes/roster.md` в редакторе и впиши свою строку, например:
   ```
   | Иван | ivan-gh | B = W2 | 16 ГБ / нет GPU / 200 ГБ | |
   ```
4. Закоммить:
   ```cmd
   git add docs/notes/roster.md
   git commit -m "docs: добавил себя в roster"
   ```
5. Запушь ветку:
   ```cmd
   git push -u origin w2/roster
   ```
6. Открой PR: зайди на https://github.com/spotyyyi123-ux/DW-1 — GitHub сам предложит кнопку
   **Compare & pull request**. Заголовок: `ONB-3: добавил себя в roster`. В описании напиши:
   ```
   Воркстрим: B (W2)
   Машина: 16 ГБ RAM, без GPU
   Проверки: pytest 17 passed, smoke OK
   ```

Готово — первый PR поехал на ревью. После мёржа — первый зелёный шаг засчитан.

## Часть 4. Как работать с git каждый день

1. **Утром:** обнови код команды:
   ```cmd
   git checkout main
   git pull
   ```
2. **Новая задача** — новая ветка от свежего main:
   ```cmd
   git checkout -b w1/baseline-tfidf
   ```
3. **Коммить часто и маленькими кусками** (один коммит = одна мысль):
   ```cmd
   git add src\dw1\extractors\body_text.py tests\test_body_text.py
   git commit -m "extract: стилометрия в body_text (burstiness, опечатки)"
   ```
   Формат всегда: `область: что сделано`. Области: `ingest`, `extract`, `model`, `campaign`,
   `explain`, `api`, `eval`, `data`, `docs`, `ci`.
4. **Пуш:** первый раз `git push -u origin w1/baseline-tfidf`, дальше просто `git push`.
5. **PR, когда задача готова.** Описание по шаблону:
   ```
   Задача: W2-1 (стилометрия)
   Что сделано: burstiness, MTLD/TTR, пунктуация, опечатки RU+EN
   Проверки: pytest 21 passed, smoke OK
   Артефакты: нет / в data\runs\...
   Лицензия данных: не трогал / <какой набор и лицензия>
   ```
6. **Если что-то сломалось** (красный pytest, конфликт, «not a git repository») — **не чини
   вслепую**. Сделай `git status` и `git log --oneline -5`, скопируй вывод и пришли наставнику.
   Безопасно: `git stash` (спрятать незакоммиченное), `git checkout -- <файл>` (отменить правку
   одного файла).

**Нельзя:** коммитить в `main`; выдумывать метрики; гонять внутренние данные заказчика через
облачные сервисы. (`.venv` и `data/raw` в `.gitignore` — git их и не возьмёт.)
