## Задача 1 — Данные и первый бейзлайн

**Нужно:** скачать датасеты и обучить простую модель «текст писал человек или ИИ».

1. Скачай в `data\raw\` шесть наборов из `docs/datasets.md` (раздел 4): CoAT, HC3-EN, LLMGen-Phishing,
   Nazario (годы 2023–2025), seven-phishing, CIFAKE. Пример команды для HuggingFace:
   ```cmd
   .venv\Scripts\python -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='RussianNLP/coat', repo_type='dataset', local_dir='data/raw/coat')"
   ```
   Nazario качается просто через браузер с monkey.org.
2. Для каждого набора запиши строку в `data\datasheet.csv` (название, ссылка, лицензия).
3. Напиши `src\dw1\models\baseline.py`: TF-IDF + HistGradientBoosting из sklearn, задача human-vs-AI.
   human = человеческие тексты CoAT + письма seven-phishing; AI = тексты CoAT от генераторов + LLMGen.
4. Научи `src\dw1\eval\harness.py` считать F1 и ROC-AUC и сохранять результат в
   `data\runs\sprint1\metrics.json`.

**Итог:** файл с первыми метриками — наша точка отсчёта, с ней будем сравнивать всё остальное.

## Задача 2 — Текстовые признаки

**Нужно:** научить систему считать «почерк» текста письма. Файлы уже созданы, внутри —
каркас и подсказки, нужно заполнить функции.

1. `src\dw1\extractors\body_text.py` — для текста письма посчитай: разброс длин предложений
   (burstiness), лексическое разнообразие (MTLD/TTR), пунктуацию, число опечаток (словари частых
   слов RU+EN, без внешних API — простые эвристики ок).
2. `src\dw1\extractors\subject.py` — длина темы, эмодзи, слова срочности («срочно», «24 часа»…),
   есть ли обращение по имени.
3. `src\dw1\extractors\cta.py` — призывы к действию: «подтвердите», «перейдите по ссылке»,
   «в течение…» (составь списки RU+EN), дедлайны.

**Итог:** три модуля кладут свои находки в `evidence` карточки письма.

## Задача 3 — Структура письма + карточка

**Нужно:** признаки по заголовкам, HTML и ссылкам + красивая карточка для показа.

1. `src\dw1\extractors\headers.py` — SPF/DKIM/DMARC (pass/fail/none), совпадает ли домен
   отправителя с Reply-To, есть ли X-Mailer.
2. `src\dw1\extractors\html.py` — три группы признаков: (A) HTML писал генератор (flex/grid,
   аккуратные семантические теги, нет Outlook-хаков `<!--[if mso]>`), (B) обфускация (zero-width
   символы, скрытые блоки), (C) «гасители» (трекеры SendGrid/Mailchimp и т.п. — признак того, что
   письмо легитимное).
3. `src\dw1\extractors\links.py` — punycode/homoglyph-домены (`xn--`), несоответствие текста
   ссылки её адресу.
4. Напиши `scripts\render_card.py`: берёт JSON-карточку письма и делает один HTML-файл с двумя
   шкалами (ИИ-происхождение / злонамеренность) и таблицей «что известно про каждый элемент».
   Чистый HTML+CSS, чтобы открывалось двойным кликом.

**Итог:** карточка письма, которую красиво покажем на защите.

## Задача 4 — Кампании + сборка демо (тимлид)

**Нужно:** группировать похожие письма в кампании и собрать всё вместе.

1. В `src\dw1\campaigns\cluster.py` сделай MinHash/LSH (библиотека `datasketch`): похожие письма →
   один кластер. Проверь на seven-phishing: топ-10 кластеров и пара примеров «почти одинаковых» писем.
2. Собери демо: прогнать модули команды на 3 письмах (ИИ-фишинг, человеческий фишинг, обычная
   рассылка), свести метрики в одну таблицу.
3. Мини-отчёт: что считаем, какие первые цифры, что доделаем в Sprint 2.

**Итог:** связка всех частей + картинка для защиты.

## Как делимся кодом (просто, без фанатизма)

- Каждый делает свою задачу **в своей ветке**: `git checkout -b w1/данные` (или `w2/...`, `w3/...`).
  Тимлид помогает с git и мёржит в main.
- Коммиты — когда удобно, сколько угодно: `git add .` → `git commit -m "что сделал"` → `git push`.
- Сломал что-то в git — не страшно, пиши тимлиду, всё чинится. Главное — не удаляй чужие файлы.
