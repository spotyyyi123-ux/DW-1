# Литературный проход: три опорные работы + релевантный контекст

Проект: DW-1 «Do Spammers Dream of Electric Sheep?» — детекция AI-assisted фишинга + explainable spam-enrichment.
Цель прохода: зафиксировать, как опорные работы определяют «AI-generated», какие данные и метрики используют, —
чтобы наши результаты были **сопоставимы**, а не «свои собственные».

---

## 1. Do Spammers Dream of Electric Sheep? (Columbia + Barracuda, IMC'25)

**Ссылка:** Wei Hao, Van Tran, Vincent Rideout, Zixi Wang, AnMei Dasbach-Prisk, M. H. Afifi, Junfeng Yang,
Ethan Katz-Bassett, Grant Ho, Asaf Cidon. *Do Spammers Dream of Electric Sheep? Characterizing the Prevalence
of LLM-Generated Malicious Emails*. Proceedings of the 25th ACM Internet Measurement Conference (IMC), October 2025.
DOI: [10.1145/3730567.3732922](https://doi.org/10.1145/3730567.3732922).
Локально: `ai-email-imc25.pdf` / `ai-email-imc25.txt` (извлечённый текст).

**Что сделано.** Первое крупномасштабное измерение использования LLM атакующими «в дикой природе».
Совместная работа с Barracuda Networks на **481 558** реальных вредоносных письмах (спам + BEC) за
февраль 2022 — апрель 2025 (до и после запуска ChatGPT).

**Ключевой методологический приём — ground truth:**
- Письма **до запуска ChatGPT** (до 12.2022) почти наверняка человеческие → отрицательный контроль;
- Положительные LLM-примеры — сами генерируют переписыванием человеческих писем локальным
  **Mistral-7B-Instruct-v0.2** (temperature=1; облачные API запрещены политикой Barracuda);
- Три детектора: **RoBERTa** (дообученный бинарный классификатор), **RAIDAR** (edit-distance-детектор,
  переписывание входов Llama-2-7b-chat), **Fast-DetectGPT** (zero-shot кривизна вероятности).

**Разбиение данных (таблица 1):** train: spam 14 646 / BEC 11 616 (02–06.2022); test pre-GPT: spam 11 751 /
BEC 18 450 (07–11.2022); test post-GPT: spam 212 748 / BEC 212 347 (12.2022–04.2025).

**Результаты:**
- RoBERTa: **FP≈0.0% / FN≈0.0%** на валидации; RAIDAR: 9.6%/10.9% (spam) и 15.3%/18.2% (BEC) → RoBERTa —
  самый точный и консервативный → его срабатывания = **нижняя оценка** доли LLM-писем;
- На апрель 2025: **≥51% спама** и **≥14.4% BEC** сгенерированы LLM; рост статистически значим
  (K-S тест, p<0.0001);
- Всплески: BEC — август 2023, спам — май 2024 (связывают с кампаниями, GPT-4o, апдейтами детекторов Barracuda);
- Голосование трёх детекторов: 87–88% срабатываний даёт один RoBERTa — слабые детекторы почти ничего
  не добавляют (это **важно для нашей фузии**).

**Характеризация (лингвистические признаки, оценка LLM по шкалам):**
| Признак | human | LLM | p-value |
|---|---|---|---|
| Формальность BEC (1-5) | 3.6 | 3.9 | p<0.0001 |
| Формальность спам (1-5) | 3.3 | 4.0 | p<0.0001 |
| Urgency спам (1-5) | 2.1 | 1.5 | p<0.0001 |
| Sophistication спам (0-100) | 56.9 | 46.3 | p<0.0001 |
| Грамматические ошибки | больше | меньше | p<0.0001 |

→ LLM-письма **формальнее, менее срочные, менее «изощрённые» по словарю, с меньшим числом ошибок**.

**Темы (LDA):** BEC — темы одинаковые у людей и LLM (payroll/direct deposit ≈55%, gift cards, «я в
совещании, напиши мне в WhatsApp»); спам — темы различаются (у LLM — промо-контент производителей).

**Главные находки для нас:**
1. Атакующие используют LLM чтобы **«полировать»** письма и генерировать **множество вариантов одного
   сообщения** — в статье показаны кластеры переписанных версий одного шаблона (CNC-производитель, 3+ варианта).
   Это прямое эмпирическое обоснование нашей ветки «кампании + скелет шаблона + класс `ai_polished`».
2. Калибровка детекторов на **pre-ChatGPT-письмах как negative control** — воспроизводимый приём
   для нашего бенчмарка.
3. Только текст (тема+тело) — HTML/картинки/QR/ссылки/заголовки не используются. Это **наш зазор**.
4. Оценка лингвистических шкал (formality/urgency/sophistication) самим LLM — переносимый в наш
   explainability-слой приём: показывает аналитику «почему» на человеческом языке.

**Ограничения:** нет публичного датасета (письма Barracuda не выкладываются); бинарные детекторы, а не
позлементная атрибуция; только EN; нет оценки устойчивости к маскировке.

## 2. SpearBot (Sichuan Univ. и др., Information Fusion)

**Ссылка:** Qinglin Qi, Yun Luo, Yijia Xu, Wenbo Guo, Yong Fang. *SpearBot: Leveraging Large Language Models
in a Generative-Critique Framework for Spear-Phishing Email Generation*. arXiv preprint
[2412.11109](https://arxiv.org/abs/2412.11109); журнальная версия: Information Fusion, Vol. 122,
DOI: [10.1016/j.inffus.2025.103176](https://doi.org/10.1016/j.inffus.2025.103176).
Локально: исходник `literature/arxiv_2412.11109/version2.tex`.

**Что сделано.** Red-team фреймворк генерации spear-phishing: jailbreak-промпты + несколько LLM в роли
**критиков** (generative-critique): письмо итеративно переписывается, пока критик не перестанет распознавать
его как фишинг. Сгенерировано **1000** писем (50 студентов + 50 работников, **10 стратегий** фишинга).

**Defenders (это их бенчмарк — берём себе как список):**
- **ML:** SVM, XGBoost, Random Forest на TF-IDF (по Barushka et al. 2018);
- **PLM:** BERT / RoBERTa ([CLS]-эмбеддинг + линейный слой), GPT-2 (EOS-эмбеддинг);
- **LLM:** in-context learning (4 демонстрации), Chain-of-Thought, ChatSpamDetector (Koide et al. 2024);
  генератор-защитник — gpt-4-1106-preview.

**Данные defenders (6 открытых наборов, через Champa et al. 2024):** CEAS_08, Enron, Ling, Nazario,
Nigerian, Assian. Пересечение признаков — только `subject`+`body`. Способ смешивания: все 6 наборов →
8:1:1 (train/val/test), в тесте сохраняются исходные сплиты наборов.

**Метрики:** Precision / Recall / F1 / Accuracy.

**Результаты (accuracy defenders на письмах SpearBot):**
| Defender | На старых данных (среднее) | На письмах SpearBot |
|---|---|---|
| SVM / XGBoost / RF (TF-IDF) | 96–98% F1 | max **21.70%** acc (XGBoost) |
| BERT / RoBERTa / GPT-2 | ~99% F1 | **3.00% / 2.20% / 1.00%** acc |
| LLM ICL / CoT / ChatSpamDetector | — | max **45.00%** acc (ICL) |

→ Обученные детекторы катастрофически переобучены под старые корпуса; LLM-defenders устойчивее, но
тоже слабы. **Аблация критика:** без критика ICL-детектор ловит 70.3% писем; с GPT-4-критиком — 59.4%;
с полным SpearBot — ещё ниже.
**Mixup-митигация (для нашей защиты — ключевой факт):** добавление в обучающую выборку всего **200**
писем SpearBot поднимает accuracy защитников с 13.25%→**89.88%** (RF) и 2.75%→**94.88%** (BERT).
→ Письма LLM **имеют узнаваемые признаки**, если защитник видел хоть немного таких примеров.
Это аргумент за обучаемые (а не только zero-shot) детекторы и за синтетическую LLM-часть нашего корпуса.

**Human-оценка:** 3 эксперта-кибербезопасника на 100 письмах признали фишингом 93% / 89% / 95%;
анкеты на читаемость/обманчивость (Nigerian-легит vs Nigerian-фишинг vs SpearBot, по 15 шт., $20 участнику).
**Стоимость генерации:** ~$0.13–0.15 за письмо (gpt-4-1106-preview, ~5.5–6.6K токенов) — «значительно
дешевле человека».

**Что берём:** список defenders и 6 наборов данных как основу нашего бенчмарка; доказательство, что
одна TF-IDF-модель не решает задачу → нужны multi-signal признаки; mixup-результат как обоснование
синтетического позитива; 10 стратегий фишинга как схему разметки intent.

**Ограничения:** генерация (офенсив) без позлементной атрибуции; нет объяснений; нет кампаний; EN;
детекторы обучены на устаревших корпусах без LLM-примеров.

## 3. Phish-Master (Peng Cheng Laboratory и др., Applied Sciences, MDPI)

**Ссылка:** Weihong Han, Junyi Zhu, Chenhui Zhang, Zhiqiang Zhang, Yangyang Mei, Le Wang. *Phish-Master:
Leveraging Large Language Models for Advanced Phishing Email Generation and Detection*. Applied Sciences
15(22):12203, 2025. DOI: [10.3390/app152212203](https://doi.org/10.3390/app152212203). Лицензия CC BY 4.0
(пригодна для цитирования/переиспользования).

**Что сделано.** Двусторонняя работа:
- **Офенсив:** алгоритм Phish-Master — Chain-of-Thought + MetaPrompt + доменные знания → 100 фишинговых
  писем; **99% evasion** в реальной кампусной сети (прошли корпоративные фильтры и дошли до получателей);
- **Дефенсив:** ансамбль ML-моделей (multi-model integration framework), обученный на **Kaggle phishing
  email dataset**, — **99.87%** детекция на тестовом наборе LLM-сгенерированных фишинговых писем.

**Что берём:** Kaggle phishing dataset как кандидат в наш корпус (проверить лицензию/доступность);
связку «MetaPrompt/CoT» как модель атаки для нашего adversarial-набора; ссылку на DetectGPT (ref_9)
как точку отсчёта curvature-методов.

**Ограничения (важно для позиционирования):** всего 100 сгенерированных писем; «99.87%» без внешнего
воспроизведения и без разбивки по генераторам — риск утечки/переобучения; нет разделения provenance/intent;
нет объяснений; нет кампаний; нет оценки устойчивости. Ровно эти зазоры мы и закрываем.

## 4. Релевантный контекст (не опоры, но пригодятся в отчёте)

- **DetectGPT** (Mitchell et al., 2023) — кривизна вероятности, пертурбации; эталонная (дорогая) точка отсчёта.
- **Fast-DetectGPT** (Bao et al., ICLR 2024, [github](https://github.com/baoguangsheng/fast-detect-gpt)) —
  дешёвая условная кривизна; используется Columbia как один из трёх детекторов.
- **ChatSpamDetector** (Koide et al., 2024) — промпт-детектор спама LLM; используется в SpearBot.
- **Hazell 2023** — LLM масштабируют spear-phishing кампании (цитируется в Phish-Master).
- **arXiv:2510.11915** — *Robust ML-based Detection of Conventional, LLM-Generated, and Adversarial Phishing
  Emails Using Advanced Text Preprocessing* — прямой сосед по «устойчивости к маскировке»; взять в related work
  и сверить их набор атак с нашим.
- **arXiv:2410.14259** (WWW'25) — *Beyond Binary: Fine-Grained LLM-Generated Text Detection via Role
  Recognition* — позлементное/ролевое определение происхождения текста; опора для нашей идеи
  per-element provenance.
- **Обзор watermarking arXiv:2504.03765** — основа раздела «applicability watermark-детекторов».
- **SemEval-2024 Task 8** — сабтаск на смешанный human-machine текст (обоснование класса `ai_polished`).

## 5. Выводы: где наша позиция и что защищать

| Зазор в литературе | Наш ответ |
|---|---|
| Бинарные детекторы, только текст (Columbia: текст; SpearBot: subject+body; Phish-Master: текст) | Позлементная атрибуция: тема, тело, CTA, HTML, изображения, QR, ссылки, заголовки, шаблон |
| Нет разделения «написано ИИ» и «злонамеренно» | Две независимые оси `ai_provenance` и `intent` + класс `ai_polished` |
| Кампании не используются (у Columbia — только наблюдение кластеров переписывания) | Кластеризация + извлечение скелета шаблона как детектор и как объяснение |
| Объяснения отсутствуют | Enrichment-карточка SOC с faithfulness-метриками (comprehensiveness/sufficiency) |
| Нет устойчивости к маскировке | Кривые деградации под 7 атаками + вывод о неубиваемости структурных признаков |
| Нет RU, нет легит-почты как hard negatives | Мультиязычность (RU+EN), отдельный эксперимент на корпоративной почте |
| Детекторы обучены без LLM-примеров (SpearBot mixup это доказал) | Синтетический LLM-позитив в обучающей выборке + кросс-генераторная проверка |

**Центральный тезис (из плана проекта):** происхождение ≠ злонамеренность. LLM-детектор говорит
«как написано», интент-ветка — «зачем». Схлопывание в один score — главная методологическая ошибка
и главный источник false positives на корпоративной почте.
