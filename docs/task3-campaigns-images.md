# Задача 3: кампании v2, Images/QR и завершение структуры письма

Код и проверочная демонстрация готовы. **Итоговый BCubed F1 на реальных топ-50
кластерах пока не измерен:** исходный корпус, эмбеддинги и ручная разметка находятся
у другого участника. Это не заменяется синтетической оценкой.

## Реализовано

- MinHash/LSH генерирует кандидатов, точный Jaccard проверяет рёбра; компоненты
  связности не пересекаются. HDBSCAN объединяет нормализованные центроиды компонент
  по импортированным sentence-transformers эмбеддингам. Шум сохраняет LSH-компоненту,
  отдельный шумовой документ получает собственный кластер. Параметры сохраняются.
- NPZ импортируется без pickle, по ID и SHA256 исходного текста, с проверкой формы,
  конечности и ненулевых норм. Перестановка строк безопасна, устаревшие векторы отклоняются.
- Каркас строится выравниванием общих токенов и эвристическими слотами NAME, AMOUNT,
  BRAND, LINK; прочие различия обозначаются VARIABLE. Это эвристика, не полноценный NER:
  имена распознаются после Dear/Здравствуйте, бренды после brand/бренда.
- Изображения из MIME, включая attachments: 64-битный DCT pHash, пять FFT-пиков с
  нормированной мощностью, EXIF, формат и размеры. Лимиты 20 MiB / 25 млн пикселей.
  Уменьшенные PNG-артефакты включаются через DW1_IMAGE_ARTIFACTS.
- OpenCV декодирует один/несколько QR. Сохраняются payload, границы и размер системы
  координат, статусы отсутствующего декодера/ошибки/недекодированного QR различаются.
  URL попадают в общий анализ ссылок; сеть и переходы не используются.
- pHash/FFT/EXIF не обученный AI-детектор: обе оси этих экстракторов остаются unknown.
  Вес измерительных признаков равен нулю, их faithfulness как классификационных
  объяснений не заявляется. Общий механизм объяснений проекта сохранён.
- Предыдущая задача: Received/Date/TZ и несоответствия доменов, тесты заголовков,
  HTML и ссылок; IDNA-нормализация, исправление opacity:0.5 и проверки POST-форм.
  Authentication-Results читается как недоверенный заголовок, подписи не проверяются.
- Карточка показывает две оси, сохраняет unknown фузии, экранирует содержимое,
  выводит скелет, слоты, изображения и QR; CSP запрещает активный контент.

## Передать коллеге по данным

Вход: UTF-8 JSONL, одна запись `{"id":"stable-id","text":"исходные subject + body"}`.
ID уникален; одинаковое объединение subject/body использовать на внешнем контуре и локально.
Нельзя заранее удалять имена/суммы/ссылки: они нужны для скелета. Не передавать внутреннюю
почту заказчика во внешний контур. Лицензию публичного корпуса записать в datasheet.

**Только внешний разрешённый контур** (локально torch/transformers не устанавливать):

```sh
pip install -e '.[embeddings]'
python scripts/export_embeddings.py --documents public.jsonl --out embeddings.npz --revision MODEL_COMMIT_SHA --public-data-approved
```

Выбрать и записать реальный commit SHA модели. Модель по умолчанию:
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Скрипт экспорта подготовлен,
но фактический запуск sentence-transformers в этой работе не выполнялся.

**Локально**, после получения NPZ:

```powershell
python -m dw1.campaigns.v2 --documents public.jsonl --embeddings embeddings.npz --out data/runs/campaign-v2
$env:DW1_CAMPAIGN_INDEX = 'data/runs/campaign-v2/campaign_index.json'
python -m dw1 tests/fixtures/campaign_email.eml --out evidence.json
```

`campaigns.json` содержит полное разбиение, параметры и сведения об эмбеддингах;
`campaign_index.json` подключается к анализу письма; `annotation.jsonl` содержит **всех**
участников топ-50 непустых кампаний (размер >1), с исходными текстами.
Онлайн-сопоставление нового письма с индексом пока лексическое (Jaccard с представителем);
семантическая кластеризация выполняется пакетно, внешняя модель в API не загружается.

## Ручная разметка и BCubed

1. Просмотреть все письма выбранных 50 кластеров. Заполнить `annotator`, `review`
   (`near-dup` или `different`) и `gold_group` для каждого письма.
2. `gold_group` — **глобальная** истинная группа near-dup: одинаковый ID для одной
   кампании даже в разных предсказанных кластерах. В смешанном кластере разделить
   разные шаблоны по gold_group. Одна бинарная метка на кластер недостаточна для BCubed.
3. Сохранить заполненный файл как `annotations-reviewed.jsonl`.
4. Запустить оценку (не менее 50 кампаний, без пропусков и повторов ID):

```powershell
make eval PY=.venv/Scripts/python.exe RUN=campaign-v2-eval CAMPAIGNS=data/runs/campaign-v2/campaigns.json ANNOTATIONS=annotations-reviewed.jsonl
# Эквивалент без make:
python -m dw1.eval.campaigns --campaigns data/runs/campaign-v2/campaigns.json --annotations annotations-reviewed.jsonl --out data/runs/campaign-v2-eval
```

Оценка сохраняет predictions.parquet, metrics.json, SHA256 входов.
Для каждого письма P=|C∩G|/|C|, R=|C∩G|/|G|; затем усреднение по письмам
и гармоническое среднее P/R. Метрика относится к индуцированному разбиению выбранной
выборки, не ко всему корпусу; одиночки и прочие кластеры вне её не оцениваются.
Неполная разметка или менее 50 кластеров приводят к ошибке, а не к фиктивному результату.

## Ограничения

HDBSCAN может объединять тематически близкие, но разные кампании; это должен выявить
ручной gold. LSH-компоненты не разделяются на семантическом шаге; цепочки near-dup могут
быть шире одного шаблона. Общий каркас может стать слишком коротким при смешанном кластере.
Внешние картинки по URL не скачиваются, OCR и детектор AI-картинок в эту задачу не входят.
PNG-артефакты — превью декодированного изображения, а не рендер недоверенного HTML письма.
Полный прежний текстовый make eval требует отсутствующих data/processed файлов;
его метрики в этой работе не пересчитывались.
